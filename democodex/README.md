# FX Lab

Демонстрационная библиотека пяти интерактивных эффектов: лава, вода, метасферы, плазма и огонь. У каждого есть UIKit- и Metal-реализация (всего 10 UIView). Swift, iOS 16+, без сторонних зависимостей.

## Вкладки и Metal Lab

Корневой `MainTabBarController` устанавливается в `SceneDelegate`:

- **Progress Bars** — `LavaProgressViewController`, существующая библиотека пяти UIKit/Metal-эффектов с A/B и CSV. Экран наследует `BenchmarkViewController`; прежний API сохранён.
- **Metal Lab** — `MetalLabViewController`, отдельный экран стресс-тестов на GPU. Выбор эффекта: «Частицы», «Вода / Физика», «Оптика / Стекло».
- **Emoji** — `EmojiParticlesViewController`, текстурный фонтан с compute-физикой и instanced rendering.
- **Showcase** — `GPUShowcaseViewController`, шесть интерактивных симуляций и 3D-сцен.
- **Compute** — `ComputeBenchmarkViewController`, N-body CPU/GPU, SPH, реакция–диффузия и Stable Fluids.

В неактивной вкладке останавливаются display link, renderer и CoreMotion. При замене эффекта старая вью останавливается и удаляется. На компактных экранах лаборатория прокручивается; жест внутри эффекта управляет эффектом. Все показатели — фактические измерения текущего окна ~0,5 с, без заданных результатов.

### Вкладка 4: GPU Showcase

Один `GPUShowcaseViewController` содержит меню из шести режимов. Одновременно создан только выбранный renderer; при переключении старая симуляция останавливается. Общие элементы: слайдер нагрузки, 60/120 FPS, пауза/продолжение, сброс, кнопка действия для эффекта. Для ткани и дыма доступны итерации решения ограничений/давления. Панель показывает Display/Completed FPS, GPU command-buffer mean/p95, CPU main-thread, workload, интервалы кадров/p95 и Presented FPS (на симуляторе `n/a`).

| Режим | Реализация | Взаимодействие / нагрузка |
| --- | --- | --- |
| Аквариум | `MetalAquariumView`, 2D SPH: плотность, давление, вязкость; два подшага. Пространственная сетка GPU: histogram → parallel prefix sum → counting-sort scatter → поиск соседей в 9 ячейках. Нет фиксированного лимита соседей на ячейку. | 1 024…16 384 частиц; палец отталкивает воду, кнопка убирает перегородку; наклон CoreMotion включается явно. |
| Рой | `MetalBoidsView`: separation, alignment, cohesion; та же отсортированная сетка, периодические границы. | 1 024…32 768 агентов; притяжение/отпугивание пальцем. |
| GPU-город | `MetalCityView`: compute frustum culling, компактизация IDs, два LOD (кубы / дальние плоские фасады), два GPU indirect draw, depth buffer. | 4 096…262 144 зданий; автоматическое движение, палец поворачивает камеру. Можно отключить culling при том же N. |
| Трассировка лучей | `MetalRaySceneView`: на `supportsRaytracing` — треугольная `MTLAccelerationStructure` и Metal intersector в compute; иначе точные аналитические sphere/plane intersections во fragment. Тени, зеркало, стекло с IOR 1.5 и полным внутренним отражением. | 2…6 последовательных сегментов пути; палец двигает свет. Аппаратный путь выводится в половинном линейном разрешении (¼ пикселей); аналитический — в полном. Эти режимы не являются A/B с одинаковой нагрузкой. |
| Ткань | `MetalClothView`: position-based dynamics, Jacobi structural/shear constraints, две закреплённые точки, сферическое препятствие, GPU triangle mesh. | 32²…128² узлов, 4/8/16 итераций; тянуть или вырезать отверстия пальцем; сброс восстанавливает ткань. |
| Объёмный дым | `MetalFluidFieldView`: 3D advection, buoyancy, источник завихрения, divergence, Jacobi pressure, projection; raymarch volume с поглощением и выборкой плотности по свету. | Сетки 24³…64³, 8/12/20 итераций давления; палец перемещает источник, кнопка включает вращение камеры. |

SPH — демонстрационная слабо сжимаемая 2D-модель с ограничением ускорения/скорости для устойчивости. Это не валидированный инженерный гидросолвер. Начальные состояния и обновления соседей находятся в ping-pong буферах, без одновременной записи в читаемые позиции. Число частиц влияет и на плотность соседей, и на стоимость проходов. Трассировка — прямое освещение и один отражённый/преломлённый путь на пиксель, без обещаний path-tracing качества или аппаратного ускорения на каждом устройстве.

### Вкладка 5: Compute Bench

`ComputeBenchmarkViewController` использует тот же интерфейс и lifecycle с отдельным каталогом. CPU здесь измеряется **для всего процесса**, включая фоновые потоки N-body; четвёртая вкладка показывает CPU main-thread.

- **N-body:** 512…65 536 тел, прямое O(N²) суммирование. Слева CPU (SIMD4, `concurrentPerform` по ядрам), справа GPU (тайлы из 256 позиций в threadgroup memory). Совпадают N, начальная спираль, массы, softening 0.002, damping 0.999, фиксированный dt=1/120. CPU выполняет один фоновый шаг за раз, не блокирует UI и показывает только законченный шаг. GPU выполняет шаг на отправленный кадр. При разной скорости симулированное время расходится: счётчики шагов показаны явно. Можно приостановить CPU; смена режима/фон отменяет старый job по поколению. Обе панели одинаково сжимают радиальные координаты при отображении, чтобы удалённые тела оставались в кадре; физические позиции и силы не меняются. Визуализация CPU требует загрузки его результата в новый неизменяемый shared buffer; GPU хранит состояние в private buffers.
- **SPH:** тот же реальный solver/пространственная сортировка, расширенный диапазон до **100 000** частиц. Поиск соседей не является O(N²) по всем телам, но при сильной кластеризации может существенно дорожать.
- **Реакция–диффузия:** Gray–Scott, две `RG32Float` текстуры, 1/10/20 шагов на кадр, 9-точечный Laplacian и инъекция реагента пальцем. Масштаб 25…100% нативного разрешения всего экрана (по каждой оси); результат этой сетки отображается в превью. При отсутствии окна, например в offscreen-тестах, берётся заданное разрешение render target. Два набора feed/kill меняют узор.
- **Чернила:** 2D Stable Fluids на сетке 128²…576², bilinear semi-Lagrangian advection, divergence, 8/12/20 Jacobi pressure iterations и projection; цветной источник следует за пальцем. Это вычисление полей, а не заранее записанная текстура.

**Что означают GFLOPS и ГБ/с:** это оценки эффективной скорости работы алгоритма, а не аппаратные peak counters. N-body использует условные ≈20 FLOP на взаимодействие (включая rsqrt как одну операцию): `20 × N² / time / 1e9`. CPU time — wall time многопоточного шага, включая его планирование. GPU time — полный успешно завершённый command buffer, включая оба render panels, а не изолированный compute encoder. Итоговые GPU числа агрегируются как выполненная работа / суммарное GPU-время. Первый кадр может включать seed; приложение не исключает его автоматически — для устойчивого результата дождитесь следующих окон.

Для Gray–Scott логический трафик оценивается как `80 × width × height × steps`: 9 чтений + 1 запись RG32Float (8 байт/texel). Кеши переиспользуют соседние texel; **logical GB/s не является измеренной пропускной способностью DRAM**. Полный GPU command buffer включает также отображение результата. Нулевое/недоступное GPU-время не заменяется выдуманной цифрой. CPU и GPU N-body работают одновременно и конкурируют за ресурсы устройства; сравнение не подменяет отдельные замеры в Instruments.

Большие N, разрешение и число шагов намеренно могут нарушать бюджет кадра. «30–60 тысяч при 60 FPS», «CPU не справится», «<0.3 мс» — проверяемые гипотезы, а не зашитые результаты. Для отчёта фиксируйте N/сетку/итерации, разрешение drawable, фактические завершённые кадры и thermal state; используйте Release на физическом iPhone.

Launch Arguments: `--gpu-showcase --showcase-effect=aquarium` (`boids`, `city`, `rays`, `cloth`, `smoke`); `--compute-bench --compute-effect=nbody` (`sph`, `reaction`, `ink`); общий `--experiment-load=0.5` (0…1).

`GPUExperimentsTests` выполняет Compute + Render всех десяти режимов, проверяет counting sort на неполной threadgroup, совпадение CPU/GPU N-body за один шаг, структуру пяти вкладок, замену/остановку renderer и расчёт throughput.

### Три эффекта лаборатории

| Компонент | Алгоритм и управление |
| --- | --- |
| `MetalParticlesView` / `ParticlesCompute.metal` | `initializeParticles` и `simulateParticles` — реальные compute kernels. Один GPU-private buffer: 1 000 000 × float4(position, velocity) = 16 000 000 байт. Слайдер 10 000…1 000 000, шаг 1 000. Счётчик N задаёт **и compute grid, и количество point vertices**. Положение пальца притягивает/отталкивает рой. Инициализация всех частиц на GPU, integer hash сохраняет распределение при больших ID. Покадровой пересылки массива с CPU нет. |
| `MetalLiquidView` / `LiquidWaves.metal` | Четыре синусоиды, глубинный градиент, вторичная волна, процедурные пена и каустика. Тап/перетягивание создают затухающую волну. Уровень воды регулируется слайдером. Опциональный CoreMotion добавляет наклон поверхности с учётом ориентации экрана. Это аналитическая модель волн, не Navier–Stokes solver. |
| `MetalGlassView` / `GlassRefraction.metal` | Raymarching объёмной линзы по деформированной сферической поверхности. Поиск входа и выхода, нормали, `refract` по закону Снеллиуса на обоих интерфейсах, отдельные IOR для RGB, Fresnel, отражение и поглощение по длине пути. Перетягивание перемещает линзу; слайдер меняет IOR/радиус. Сцена за линзой — динамическая процедурная сетка, световые ленты и кольца. Это ограниченная модель оптики с конечным числом шагов, а не полноценный path tracer; UIKit-вью за MTKView она не захватывает. |

Общий `MetalAnimationView` кодирует compute и render в одном command buffer (строго последовательно). Для частиц используется один buffer с автоматическим hazard tracking; следующий кадр идёт в той же command queue. Максимум три кадра в полёте, при занятом семафоре кадр пропускается. Render targets идут в полном физическом разрешении вью; входных изображений у эффектов нет. Выделение GPU-памяти может не удаться — экран показывает ошибку, другие режимы остаются доступны.

CoreMotion включается **только переключателем пользователя** и только для активной воды. Добавлен `NSMotionUsageDescription`. Если датчиков нет (например, в симуляторе), переключатель недоступен, тапы продолжают работать. Уход с экрана или в фон останавливает обновления датчиков.

### Метрики лаборатории

- **Display FPS** — частота CADisplayLink; рядом доступны средний/p95 интервал кадров.
- **GPU Frame** — среднее `(gpuEndTime − gpuStartTime) × 1000` успешно завершённых command buffers. Для частиц включает compute **и** point rendering. Начальная инициализация buffer идёт отдельно. Недоступное значение отображается как «—».
- **CPU · Main Thread** — `thread_info(THREAD_BASIC_INFO)` именно главного потока: разность user + system CPU time / wall time × 100. Это отличается от CPU всего процесса во вкладке Progress Bars. 100% означает занятое ядро главного потока, накладные расходы UI/профилировщика включены.
- **Active Entities** — N частиц, 4 аналитические волны или 1 линза.
- **Completed FPS** — количество успешно завершённых command buffers за окно.
- **Presented FPS** — количество drawable с положительным `presentedTime` в `addPresentedHandler`. На iOS Simulator этот API отсутствует в SDK, поэтому показано `n/a`. Поздние callbacks старого эффекта отбрасываются по поколению измерений.

При движении слайдера метрики продолжают обновляться и усредняются по окну, которое может включать несколько значений N. Смена эффекта/целевой частоты очищает окно. Для отчёта зафиксируйте N, частоту, физический размер drawable и дождитесь нескольких стабильных окон. Запрос 120 FPS ограничен возможностями экрана и политикой системы.

**Цели 60–120 FPS при миллионе частиц, GPU воды <0,3 мс и отсутствие заметной задержки UI не гарантируются.** Проверяйте Release на физическом iPhone без отладчика, с записью thermal state и Low Power Mode. FPS интерфейса, завершение GPU и презентация — разные показатели. GPU-время не является временем реакции на касание. Overlay не измеряет input-to-photon latency; получение drawable/драйвер также может занимать время. Результаты симулятора не характеризуют iPhone.

Источники: [Metal compute encoders](https://developer.apple.com/documentation/metal/mtlcomputecommandencoder), [GPU calculations](https://developer.apple.com/documentation/metal/performing-calculations-on-a-gpu), [drawable presentation](https://developer.apple.com/documentation/metal/mtldrawable/addpresentedhandler(_:)), [Core Motion](https://developer.apple.com/documentation/coremotion).

## Emoji: текстурный стресс-тест

Третья вкладка содержит четыре режима: огонь 🔥, ракета 🚀, сердца ❤️ и микс 🎲. В миксе используются также 💥 и 🦊. Слайдер задаёт **1 000…200 000 инстансов** с шагом 1 000; размер плашки выбирается отдельно (16/32/48 физических пикселей). Тап создаёт всплеск, перетягивание перемещает источник и отталкивает частицы. После отпускания фонтан продолжает работать из последней точки. Кнопки «Всплеск» и «Пауза» доступны также без жестов.

- `EmojiTextureProvider.swift` рисует нативные цветные символы через `UIGraphicsImageRenderer` и загружает `MTLTexture` через `MTKTextureLoader`. Атлас 640×128 (пять тайлов 128×128 с прозрачными полями) и mipmaps кешируются по устройству и набору строк. Создание — при первом открытии эффекта, до начала измерений; смена режима использует тот же атлас. Есть отдельный `texture(for:device:)` для одной строки. Покадровой генерации изображений нет.
- `EmojiPhysics.metal` и общий `EmojiParticleTypes.h`: position, velocity, angle, angularVelocity, age/lifetime, индекс символа, burst ID и размер. Гравитация, отражение от боков, отталкивание, вращение и повторное рождение считаются на GPU. Тап/движение запускают дополнительный всплеск части пула. Шаг симуляции ограничен 1/30 с для устойчивости при пропусках.
- `EmojiRender.metal`: `vertex_id` строит шесть вершин quad, `instance_id` выбирает частицу и участок атласа. Все эмодзи, включая смешанные типы, рисуются **одним** `drawPrimitives(type: .triangle, vertexStart: 0, vertexCount: 6, instanceCount: N)`. У Metal нет перегрузки с параметром `indexed` в этой форме; индексный буфер для шести сгенерированных вершин не нужен. Прозрачность — premultiplied alpha, края и время жизни плавно затухают.
- `MetalEmojiParticlesView.swift`: использует общий MTKView backend и один GPU-private буфер на 200 000 × 48 байт = **9 600 000 байт**, без покадровой передачи массива частиц с CPU. Атлас занимает ~320 KiB без mipmaps. Drawable и прочие ресурсы занимают дополнительную память.

**Active Emoji Count отличается от N.** N — нагрузка compute и число отправленных инстансов. GPU отдельно считает живые плашки, чьи повёрнутые bounds пересекают viewport. Частицы за границами или в момент рождения/смерти не входят в активный счётчик. Перекрывающие друг друга плашки учитываются по отдельности; это не число уникальных видимых пикселей. Часть фонтана может находиться за верхней границей, поэтому активных может быть меньше N.

Подсчёт использует локальную редукцию в группах по 256 потоков и одно атомарное сложение на группу. Полная последняя группа безопасно обрабатывает N, не кратное 256. После render GPU копирует **только четыре байта** счётчика в свободный shared-slot. Три слота защищены от повторного использования до завершения CPU-чтения; callback не блокирует main thread. Метрика приходит асинхронно и обновляется вместе с overlay раз в ~0,5 секунды. Старые callbacks после остановки/сброса отклоняются по поколению. Значение 0 сохраняется как измеренный ноль; отсутствие данных показывается «—».

Overlay: Display FPS, GPU Frame (compute + draw + счётчик/readback), CPU главного потока, Active Emoji Count. Внизу — число инстансов, один draw call, Completed FPS и Presented FPS (на симуляторе — `n/a`). При смене количества показатели продолжают обновляться по скользящим окнам текущего профилировщика. Пауза, уход с вкладки и фон останавливают и рендер, и профилировщик.

**CPU <5% при 100 000 эмодзи и 60/120 FPS — цели измерений.** Они зависят от устройства, размера плашки, перекрытия прозрачных текстур, разрешения drawable и частоты. Один draw call снижает CPU-затраты, но не устраняет fill-rate/overdraw и нагрузку на GPU. На физическом iPhone используйте Release без отладчика и фиксируйте N и размер; симулятор не подтверждает аппаратную гипотезу.

Launch Arguments: `--emoji-particles`, `--emoji-count=100000`, `--emoji-mode=3` (0 — огонь, 1 — ракета, 2 — сердца, 3 — микс).

Тесты исполняют compute и instanced render 100 000 текстурных quad, проверяют кеш/прозрачность всех пяти glyph, переключение режимов, видимость и хвост неполной threadgroup, гравитацию/вращение/отталкивание, pause/resume и остановку третьей вкладки.

Источники: [Instanced draw](https://developer.apple.com/documentation/metal/mtlrendercommandencoder/drawprimitives(type:vertexstart:vertexcount:instancecount:)), [MTKTextureLoader](https://developer.apple.com/documentation/metalkit/mtktextureloader).

## Запуск

1. Откройте `democodex.xcodeproj`, выберите схему `democodex` и iPhone.
2. Для физического устройства укажите свою Signing Team.
3. Выберите эффект в сегменте «Лава | Вода | Капли | Плазма | Огонь», затем движок UIKit / Metal. Слайдер задаёт заполнение воды/лавы, размер капель, энергию плазмы или интенсивность огня. Под превью есть подсказка для перетягивания.
4. Выберите 60 или 120 FPS. 120 доступен на экранах с соответствующей максимальной частотой; это запрос системе, фактическая частота может быть ниже.
5. Нажмите «Запустить A/B-тест» для выбранного эффекта: 2 секунды прогрева, не менее 10 секунд измерения, затем второй режим с таким же прогревом и измерением. Длительность фаз округляется до окна профилировщика (~0,5 секунды). Превью автоматически возвращается в видимую область; ручная прокрутка прерывает тест, чтобы исключить замер скрытого рендерера.
6. «Экспорт CSV» открывает системное меню сохранения/отправки. В CSV есть выбранный эффект, отдельные окна, агрегаты и условия теста. Пустая ячейка означает отсутствие измерения.

Для воспроизводимого сравнения используйте **Release на физическом iPhone без отладчика**. В Xcode: Edit Scheme → Run → Build Configuration → Release, отключите Debug executable. Instruments запускается через Product → Profile (Release уже настроен в общей схеме).

## Реализации

- `StandardLavaProgressBarView.swift`: CAGradientLayer, 14 движущихся радиальных градиентов, CAShapeLayer для маски заполнения и яркий мениск. Геометрия обновляется через общий CADisplayLink, без растровой текстуры и искусственной нагрузки.
- `MetalAnimationView.swift`: общий MTKView с ручным `draw()` из того же CADisplayLink. Полноэкранный треугольник, `setFragmentBytes`, максимум три кадра в полёте, с пропуском кадра при занятом семафоре. Получение drawable зависит от расписания презентации платформы. Неактивный рендерер не обновляется.
- `LavaShader.metal`: пятикратный fBm с domain warping, тёмно-красная/оранжевая/жёлтая палитра, белый мениск. Uniforms: `resolution` в физических пикселях, `progress`, `time`. Первые 16 байт общих uniforms совместимы с исходным lava-шейдером; общий `EffectUniforms` занимает 32 байта и дополнительно содержит normalized touch, interaction strength и padding.
- `PerformanceProfiler.swift`: общий CADisplayLink, процессное CPU-время через `getrusage`, потокобезопасный сбор Metal completion callbacks. Поколения измерений отбрасывают запоздалые GPU-ответы после смены режима/сброса.
- `BenchmarkRun.swift`: прогрев, два последовательных режима, агрегирование и CSV.
- `BenchmarkViewController.swift`: программный UIKit-интерфейс, график, панель UILabel, управление и экспорт. Компактный overlay FPS / Frame Interval / CPU поверх превью позволяет видеть метрики вместе с эффектом; подробная телеметрия расположена ниже. В фоне и при уходе с экрана цикл останавливается. Незаконченный тест прерывается при потере активности и повороте экрана.

## Новые эффекты и API

| Эффект | UIKit | Metal | Взаимодействие |
| --- | --- | --- | --- |
| Вода | `StandardWaveView`: CAShapeLayer + пересчёт UIBezierPath | `MetalWaveView` / `WaveShader.metal`: 4 синусоиды, шумовая пена | Вертикальная координата меняет уровень, по поверхности проходит затухающая рябь |
| Капли | `StandardMetaBallView`: поле потенциалов, marching triangles, градиентная маска | `MetalMetaBallView` / `MetaBallShader.metal`: сумма R² / distance², smoothstep, блики | Пять центров притягиваются к пальцу, контур сливается |
| Плазма | `StandardPlasmaView`: 10 радиальных CAGradientLayer, rotation/opacity | `MetalPlasmaView` / `PlasmaShader.metal`: вложенный fBm / domain warping | Палец меняет положение и завихрение энергии |
| Огонь | `StandardFireView`: три CAEmitterLayer для пламени, дыма и искр | `MetalFireView` / `FireShader.metal`: вертикальный fBm, температурная палитра, дым, искры | Положение пальца задаёт ветер |

`BenchmarkableAnimationView: UIView` содержит `progress`, `startAnimation()` и `stopAnimation()`. Все компоненты наследуются от `AnimationView`; Metal-компоненты используют общий `MetalAnimationView` с ограничением кадров в полёте и профилированием. `AnimationEffect` хранит каталог и фабрику. Контроллер удаляет старую вью и добавляет только одну активную, останавливая её перед заменой. Выбранный эффект записывается в `BenchmarkRun` и CSV.

Для самостоятельного встраивания:

```swift
let water = MetalWaveView(frame: CGRect(x: 20, y: 100, width: 320, height: 220))
water.progress = 0.6
view.addSubview(water)
water.startAnimation()
// При уходе с экрана:
water.stopAnimation()
```

В самостоятельном режиме `AnimationView` создаёт CADisplayLink с weak target и приостанавливает его при удалении из окна/уходе в фон. В benchmark контроллер ставит `externallyDriven = true` и вызывает `render(time:)` из общего профилировщика. `startAnimation()` разрешает обновления, `stopAnimation()` их запрещает, сбрасывает касание и останавливает эмиттеры. Удалённые компоненты не продолжают анимацию. Прогресс нормализуется в 0…1; NaN и infinity сбрасываются в 0.

UIKit-капли используют публичный CPU-пересчёт контура, без приватного CAFilter. Поле метасфер — implicit surface по потенциалу, математически оно не является точной SDF. У UIKit используется сетка до 96×64; Metal вычисляет поле на каждом пикселе. CAEmitterLayer также использует Core Animation/GPU и не является исключительно CPU-рендерером. Искажение воздуха в FireShader имитируется внутри процедурного фона; соседние UIKit-вью не преломляются. Формы и визуальная сложность двух движков различаются.

## Что именно измеряется

| Метрика | Определение | Ограничения |
| --- | --- | --- |
| Display FPS | `1000 / mean(Δ CADisplayLink.timestamp, ms)` | Частота display link, не число гарантированно показанных кадров приложения. |
| Frame Interval | Среднее и p95 интервала CADisplayLink | Включает пропуски, не равно времени исполнения шейдера. График показывает среднее каждого окна, до 60 окон. |
| CPU · процесс | `Δ(user + system CPU seconds) / Δwall seconds × 100` | Все потоки процесса и профилировщик. 100% = одно ядро; возможно >100%. Внешний Core Animation render server сюда не входит. |
| CPU Update / Encode | `CACurrentMediaTime()` вокруг обновления слоёв либо получения drawable, кодирования и commit | CPU-работа приложения; не вся отрисовка Core Animation. |
| GPU · Metal | `(gpuEndTime − gpuStartTime) × 1000` внутри completed handler | Только наш Metal command buffer. Если GPU timestamp недоступен, показывается «—». Для CA GPU-время неизвестно. |
| Command Latency | CPU start → completed handler через `CACurrentMediaTime()` | Включает получение drawable, кодирование, очередь, GPU и задержку callback. Это не чистое GPU-время и не input-to-photon latency. |
| Completed FPS | Количество успешно завершённых Metal command buffers / длительность окна | Проверяет, что Metal действительно завершает работу; не гарантирует презентацию каждого drawable. |

Агрегированный FPS считается по всем интервалам, CPU % взвешивается по длительности окон, время CPU/GPU — по всем доступным кадрам, p95 — по всем интервалам. UI обновляется раз в ~0,5 секунды. Прогрев исключён. Запрос 120 FPS включён также через `CADisableMinimumFrameDurationOnPhone`.

Источники: [CADisplayLink](https://developer.apple.com/documentation/quartzcore/cadisplaylink), [GPUStartTime](https://developer.apple.com/documentation/metal/mtlcommandbuffer/gpustarttime), [addCompletedHandler](https://developer.apple.com/documentation/metal/mtlcommandbuffer/addcompletedhandler(_:)).

## Протокол сравнения

- Одинаковые устройство, сборка, выбранный эффект, размер превью, параметр, яркость экрана, целевой FPS и настройки питания.
- Запишите модель iPhone, версию iOS, состояние батареи и нагрев. CSV сохраняет тип устройства, iOS, Debug/Release, simulator/device, размер drawable, FPS, прогресс, thermal state и Low Power Mode. Для отчёта укажите точную аппаратную модель отдельно (`UIDevice.model` обычно возвращает просто iPhone).
- Повторите минимум 5 запусков в каждом порядке: сначала выберите UIKit и запустите A/B, затем выберите Metal и повторите. Сравнивайте распределения между запусками; один прогон зависит от порядка и нагрева.
- Отдельно проверьте прогресс 0%, 50%, 100%. При 0% shader быстро возвращает фон, поэтому его стоимость отличается от полного заполнения. Внутри одного A/B выбор эффекта, движка, параметр и касания заблокированы; обе реализации создаются заново с локальным временем 0 и одинаковым прогревом. Лава, вода и огонь при нулевом параметре возвращают фон; у капель и плазмы нулевой параметр задаёт минимальные размер/энергию.
- При изменении энергосбережения/thermal state во время измерений результат помечается; для итогового отчёта повторите такой прогон. Симулятор подходит для проверки поведения, но его GPU и CPU не характеризуют iPhone.
- Сверьте CPU в Instruments Time Profiler; кадры Core Animation — Animation Hitches/Core Animation; Metal — Metal System Trace/GPU tools на поддерживаемом устройстве. Overlay не измеряет GPU Core Animation, энергопотребление или VRAM.

**Гипотеза, не обещание результата:** UIKit/Core Animation также выполняет композицию на GPU. Для небольшого градиентного бара baseline может быть очень дешёвым; процедурный fBm может оказаться дороже по GPU. Значения «15–25% против 1–3%» и «<0,5 мс» не зашиты в приложение и требуют проверки. Визуально реализации близки по назначению, но разные алгоритмы не дают попиксельно одинаковую картинку. Это сравнение двух конкретных реализаций.

У процедурных Metal-эффектов библиотеки нет входных растровых текстур; Emoji использует кешированный атлас. **Это не нулевое потребление VRAM:** drawable, pipeline и системные буферы занимают память. Лава, вода, капли и плазма в UIKit обходятся без изображений. UIKit-огонь использует одну небольшую радиальную текстуру, созданную программно, для частиц CAEmitterLayer.

## Проверки

`LavaLabTests` входит в общую схему: **Product → Test**. Проверяются расчёт FPS/p95 и CPU, исключение прогрева, переключение A/B, изоляция запоздалых и конкурентных Metal callbacks, CSV, clamp прогресса, замена всех 10 вью, lifecycle start/stop, взаимодействие с водой и притяжение капель. Offscreen-тесты реально исполняют шейдеры библиотеки, проверяют 0/50/100% для лавы и изменение новых эффектов по времени, касанию и параметру.

```sh
xcodebuild -project democodex.xcodeproj -scheme democodex \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' test
```

Metal Lab дополнительно проверяется GPU-тестами: реальный compute + draw миллиона точек, границы активного диапазона, направление силы, анимация/рефракция и влияние наклона воды. Проверяются структура вкладок, lifecycle, main-thread CPU sampler и фильтрация старых презентаций.

Для запуска лаборатории через Launch Arguments: `--metal-lab`, `--lab-effect=particles` (также `liquid`, `glass`), `--particles-count=1000000`.

Для ручных smoke-проверок библиотеки поддерживаются Launch Arguments: `--engine-uikit`, `--progress-zero`, `--progress-full`, `--benchmark`, `--effect=wave` (также `lava`, `metaBall`, `plasma`, `fire`). Они не меняют правила сбора метрик. Debug/Simulator цифры не являются результатами аппаратного сравнения.
